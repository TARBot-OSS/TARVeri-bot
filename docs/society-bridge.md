# TARClub Society Bridge: Setup Guide

This guide links a TARClub society server to TARVeri so that TARClub can check whether a member is a verified student. You need access to both bots' `.env` files and the `Administrator` permission in both servers.

## How it works

TARVeri issues a signed pairing token for one society server. The society's administrator redeems it in TARClub. TARClub checks the signature with a secret that only the bot hosters know, so a token cannot be forged without that secret.

Token format: `TARV-<society_guild_id>-<unix_timestamp>-<signature>`. It is valid for 24 hours.

## 1. Create the shared secret (once, by the hoster)

The secret is not generated by either bot. You create it and put the same value in both bots' environments.

```bash
openssl rand -hex 32
```

| Bot | Variable |
| --- | --- |
| TARVeri | `TARVERI_BRIDGE_SECRET` |
| TARClub | `TARCLUB_SHARED_SECRET` |

Restart both bots after setting it. Keep the value out of chat, tickets and git. If it leaks, generate a new one, update both bots and re-pair every society, because the old tokens no longer verify.

Without the secret, TARVeri refuses to issue tokens and TARClub rejects every token.

## 2. Issue a token (TARVeri administrator)

In the TARVeri server run:

```
/admin society_bridge pair society_guild_id:<society server ID> notes:<club name>
```

To copy a server ID, enable Developer Mode in Discord and right-click the server. The token is shown only to you. Send it privately to the society's administrator.

## 3. Redeem the token (society administrator)

TARClub must already be in the society server. Run:

```
/integrate-tarveri link token:<token>
```

TARClub confirms the link. From then on, committee appointments require the member to be a verified TARVeri student. You can check the state at any time:

```
/integrate-tarveri status
/integrate-tarveri audit
/integrate-tarveri toggle-enforce enabled:<True|False>
```

## Managing pairings (TARVeri administrator)

```
/admin society_bridge list
/admin society_bridge unpair society_guild_id:<society server ID>
```

## How a member counts as verified

TARClub treats a member as a verified student if they hold one of TARVeri's role names: `TARUMT Verified`, a faculty role (`FAFB`, `CPUS`, `FOCS`, `FCCI`, `FOAS`, `FOBE`, `FSSH`, `FOET`), or a study-level role (`Degree`, `Diploma`, `Foundation`, `Postgraduate`). Servers that still have the older `Bachelor's Degree` role also count. Roles with similar names, such as `Student Council`, do not count. If the member has none of these roles and both bots run on the same machine, TARClub reads TARVeri's database read-only. Set `TARCLUB_TARVERI_DB_PATH` to its location.

## Troubleshooting

| Message | Cause and fix |
| --- | --- |
| `TARVERI_BRIDGE_SECRET is not set` | Set it in TARVeri's `.env` and restart. |
| `TARCLUB_SHARED_SECRET is not configured` | Set it in TARClub's `.env` and restart. |
| `Invalid cryptographic token signature` | The two secrets differ, or the token was altered. Compare both values and issue a new token. |
| `Token has expired` | Issue a new token. Tokens last 24 hours. |
| `Token was issued for guild X, not this server` | The token was made for a different server ID. Issue one for this server. |
| `Invalid token structure` | The token was truncated when copied. Copy it again in full. |
